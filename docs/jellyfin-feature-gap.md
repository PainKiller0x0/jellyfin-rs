# Jellyfin 功能差距基线

对比基准为仓库内的 `jellyfin/` 上游源码。本文不统计 HTTP API 路由数量，重点记录用户可感知的服务能力和管理工作流。

状态定义：

- `已有`：核心工作流可用。
- `部分`：已有实现，但行为、配置面或内容类型覆盖尚未达到 Jellyfin。
- `缺失`：当前没有可用实现。

## P0：媒体库

| 能力 | 状态 | 当前差距 | 下一步 |
| --- | --- | --- | --- |
| 创建、删除媒体库 | 部分 | 后端支持，管理端仅提供电影、剧集、音乐、混合内容四种类型 | 补齐家庭视频、音乐视频、书籍、照片等已被扫描器支持的类型 |
| 媒体路径管理 | 部分 | 可添加、删除和选择目录；后端支持路径更新，但管理端没有编辑入口 | 增加路径编辑和修改前校验 |
| 媒体库改名 | 部分 | 后端支持，管理端没有入口 | 增加编辑媒体库工作流 |
| 每库选项 | 部分 | 选项 JSON 可以保存，但管理端没有入口，扫描器仅使用 `EnablePhotos` | 增加设置界面，并让启用状态、实时监控和提供者策略生效 |
| 实时文件监控 | 部分 | 启动时只读取一次路径；运行后新增路径不会进入原生监听；任何变化会触发全库扫描 | 动态重载监听路径，按发生变化的媒体库定向扫描 |
| 手动扫描 | 部分 | 只能全库扫描；只有“已启动”提示，没有持续状态和进度 | 增加每库扫描、运行状态、最近结果和进度 |
| 增量入库 | 部分 | 路径指纹可在 NFO 和数据库写入前跳过未变化项目；变更项目批量写入 PostgreSQL 持久队列并通过租约恢复，但 `media_items` 仍逐项 upsert | 批量 CreateItems/UpdateItems 和集合式删除对账 |
| 扫描资源隔离 | 部分 | 前台/后台 PostgreSQL 连接池已隔离；空闲时并行 refresh，浏览或播放活跃时只启动一个新后台 worker | 补充真实负载延迟基准、写入批处理和管理端队列指标 |
| 本地元数据 | 部分 | 支持 NFO、旁路图片、字幕；格式和保存器覆盖不完整 | 对齐 Jellyfin NFO 读写、锁定字段与本地保存策略 |
| 在线元数据 | 部分 | 主要支持 TMDb 和豆瓣，支持部分每类型策略 | 补充提供者排序、按库语言/国家、图片类型策略和失败重试状态 |
| 媒体识别 | 部分 | 电影、剧集、音乐、书籍、照片、家庭视频、音乐视频已有解析器 | 持续对齐 Jellyfin Naming 测试集、特殊内容和多版本规则 |
| 章节图、Trickplay、片头片尾 | 部分 | 各模块存在，但没有统一的每库设置和任务状态 | 接入媒体库选项、计划任务与资源限流 |
| 媒体库浏览管理 | 缺失 | 管理端只能维护库本身，不能按库浏览条目、筛选异常、批量操作 | 增加库内条目视图、未识别/缺图/探测失败筛选和批量刷新 |

## P1：播放与用户体验

| 能力 | 状态 | 当前差距 |
| --- | --- | --- |
| 直接播放与 Range | 已有 | 本地文件和 STRM 为当前主路径 |
| 播放进度、收藏、已播放 | 已有 | 仍需扩大客户端回归矩阵 |
| 转码和自适应 HLS | 缺失 | Jellyfin 的转码决策、会话管理和码率自适应尚未实现 |
| 字幕处理 | 部分 | 支持外挂字幕直出和扫描，缺在线字幕提供者与完整转换链路 |
| 多版本与附加内容 | 部分 | 扫描器已有电影堆叠、剧集版本和 extras 逻辑，管理体验不足 |
| 播放队列、远程控制 | 部分 | 有会话与部分控制能力，未达到 Jellyfin 完整行为 |
| SyncPlay | 缺失 | 尚无可用实现 |

## PostgreSQL 与性能约束

后续媒体库改动必须满足以下约束：

1. 前台请求与后台扫描使用独立连接池，后台池不得耗尽前台连接。
2. 扫描写入使用短事务或可中断批次，不允许用长事务覆盖完整媒体库。
3. 文件事件优先做单库或路径级增量处理，不应默认触发全库扫描。
4. 高频浏览查询必须有与过滤、排序相匹配的 PostgreSQL 索引，并用真实数据执行 `EXPLAIN (ANALYZE, BUFFERS)` 验证。
5. 媒体探测、图片生成、指纹和在线元数据任务必须有独立并发上限；播放活跃时应主动降低后台工作速率。
6. 所有扫描状态、耗时、发现数、写入数、跳过数和失败数都应可观测。

## 实施顺序

1. 媒体库设置、动态监听、单库扫描和扫描状态。
2. PostgreSQL 批量入库、路径级增量队列和前台延迟基准。
3. 媒体库内容管理、异常筛选和批量元数据操作。
4. 播放能力、用户策略和计划任务对齐。
5. 插件、直播电视、DLNA 等独立大型子系统。
